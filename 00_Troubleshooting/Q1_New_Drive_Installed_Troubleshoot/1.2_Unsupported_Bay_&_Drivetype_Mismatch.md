# Project 2 — Enterprise Drive Validation

## Troubleshooting Question 1

### Q1.2 — Unsupported Bay / Drive-Type or Platform-Topology Mismatch

## Top-Level Problem

> A new enterprise drive has been installed, but it is not detected or does not behave as expected.

This case specifically covers an **unsupported bay, drive-type, or platform-topology mismatch**.

A drive is not inherently required to use one particular bay. The relevant question is whether the selected bay/backplane/path supports that drive type and configuration.

---

## Expected Flow

```text
Drive
   ↓
Supported bay
   ↓
Supported backplane/path
   ↓
Required controller / PCIe / HBA path
   ↓
Platform detection
   ↓
OS detection
   ↓
Drive usable
```

---

## Troubleshooting Approach

### 1. Identify the Drive and Location

Determine:

- Drive type
- Drive model
- Physical bay
- Server model
- Backplane type
- Platform topology
- Expected supported configuration

### 2. Verify Bay / Backplane Capability

Determine whether the installed bay/path supports the drive type.

Examples:

```text
SAS/SATA-only path
NVMe path
AnyBay / multi-protocol supported path
```

The exact capability is platform-specific and must be verified from the server/storage configuration.

### 3. Compare Actual vs Supported Configuration

Determine:

```text
Actual configuration
        vs
Supported configuration
```

Example:

```text
NVMe SSD
    ↓
Bay 2
    ↓
SAS/SATA-only path
    ↓
Unsupported combination
```

### 4. Verify Platform Topology Where Relevant

A supported bay may still provide a different path than required by a specific qualification test.

Therefore verify:

```text
Bay
 ↓
Backplane
 ↓
Controller / HBA / PCIe path
```

### 5. Correct the Configuration

If the combination is unsupported:

```text
Move drive to documented supported bay/path
        ↓
Follow approved installation procedure
        ↓
Verify platform detection
        ↓
Verify OS detection
```

### 6. Establish RCA

Example evidence:

```text
Drive type → NVMe
Installed bay → Bay 2
Backplane → SAS/SATA-only
NVMe support → Not available on this path
Same drive moved to documented NVMe-capable path
        ↓
Drive detected
```

### Root Cause

> The drive was installed on a bay/backplane path that did not support the drive type or required platform topology.

### Important Distinction

```text
Drive installed in Bay 4 instead of Bay 3
        ≠
Automatically a problem
```

Location is relevant only when the bay/path capability or the specific qualification topology makes it relevant.

---

## Interview Presentation

> When a newly installed enterprise drive is not detected, I verify that the physical bay and backplane actually support that drive type and the required platform topology. I correlate the drive model and type with the server configuration, backplane capability and storage path. If the combination is unsupported, I move the drive to a documented supported path using the approved procedure and verify detection at the platform and OS levels. I consider the configuration mismatch the root cause only when the evidence shows the original path was unsupported and the drive works correctly on a supported path.
